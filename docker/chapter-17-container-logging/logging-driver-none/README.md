# Docker Logging Driver: none

## Overview

Docker supports multiple logging drivers. Most containers use the
default **json-file** driver, which stores logs on the host.

However, Docker also allows disabling logging entirely using:

    --log-driver none

This example demonstrates what happens when a container runs with **no
logging driver**.

Key behavior:

-   The container still runs normally.
-   The application still writes logs to stdout.
-   Docker **does not store those logs anywhere**.
-   The `docker logs` command will **not work**.

This is sometimes used in high‑performance environments where logs are
handled directly by the application or an external logging agent.

## Application Behavior

The Python application continuously prints log messages.

Example output generated by the application:

    Log line 1 - application generating logs
    Log line 2 - application generating logs
    Log line 3 - application generating logs

Even though the application produces logs, Docker will not store them
when the logging driver is disabled.

------------------------------------------------------------------------

## Running the Example

Run:

    ./run.sh

The script performs these steps:

1.  Builds the Docker image
2.  Runs the container in **detached mode**
3.  Disables logging with `--log-driver none`
4.  Shows the running container
5.  Attempts to fetch logs

Docker run command used internally:

    docker run -d \
      --name logging-driver-none \
      --log-driver none \
      logging-driver-none

------------------------------------------------------------------------

## Observing the Behavior

The script attempts to run:

    docker logs logging-driver-none

Expected result:

    Error response from daemon: configured logging driver does not support reading

This demonstrates that Docker **cannot retrieve logs when logging is
disabled**.

## Inspecting Logging Configuration

You can verify the logging driver using:

    docker inspect logging-driver-none --format='{{.HostConfig.LogConfig.Type}}'

Expected output:

    none

## Why Disable Logging?

Disabling container logging is useful in scenarios where:

-   Logs are sent directly to external collectors
-   Applications manage their own logging pipeline
-   High‑performance workloads generate extremely large logs
-   Disk usage must be minimized

Common external logging solutions:

-   Fluent Bit
-   Fluentd
-   Loki
-   Elasticsearch
-   Datadog

------------------------------------------------------------------------

## Important Production Insight

If the logging driver is set to **none**, then:

-   `docker logs` cannot retrieve logs
-   Docker will not store logs
-   Debugging becomes harder unless another logging system is configured

Therefore, this configuration should only be used when a **separate
logging system already exists**.
